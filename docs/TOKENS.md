# Схема токенов темы (версия схемы 1)

Токены - это параметры визуала как данные. Один набор токенов питает:

- сессию (Quickshell, виджеты, панели, Hyprland-часть оформления);
- экран входа SDDM (экспорт подмножества в `theme.conf`, этап 11);
- экран блокировки hyprlock (генерация конфига, этап 12).

Код Liquid Glass в сессии и на экране входа разный (QML-шейдер внутри SDDM,
эффекты Hyprland в сессии), но палитра и ключевые параметры материала общие.
Это закрывает требование 2.3 из ТЗ.

Файл-пример значений: `docs/tokens.default.json` (стартовый вариант Aurora Glass).
Реализация (этап 4): `hyprown/theme.py` (схема, валидатор, миграции, палитра из обоев),
готовые темы в `themes/*.json`, оболочка читает итог из `~/.local/state/hyprdesk/tokens.json`.

## 1. Принципы

1. Виджет и любая тема читают только токены. Жёстко прописанных цветов,
   радиусов и длительностей в коде виджетов быть не должно.
2. Токены - это данные: JSON с полем `schema_version`. Старые файлы
   мигрируются, а не отбрасываются.
3. Ошибка в токенах не блокирует вход и запуск. Если файл битый или не проходит
   проверку, берутся встроенные значения по умолчанию и пишется запись в журнал.
4. В токенах нет секретов: ни паролей, ни токенов доступа, ни путей к
   приватным данным.
5. Единицы не зависят от масштаба монитора. Масштаб и расположение лежат в
   конфиге мониторов (этап 13) и применяются во время работы, а не хранятся
   в токенах.
6. Запись файла токенов атомарная: сначала временный файл, потом переименование.

## 2. Структура

```
{
  "schema_version": 1,
  "id": "aurora-glass",
  "name": "Aurora Glass",
  "palette":    { ... },
  "material":   { ... },
  "motion":     { ... },
  "shape":      { ... },
  "typography": { ... },
  "effects":    { ... }
}
```

### 2.1 meta

| Поле | Тип | Описание |
|---|---|---|
| `schema_version` | int | Версия схемы. Сейчас 1. |
| `id` | string | Стабильный идентификатор набора (латиница, дефис). |
| `name` | string | Отображаемое имя. |

### 2.2 palette

Роли цветов, а не конкретные значения "для виджета". Формат цвета:
`#RRGGBB` или `#RRGGBBAA`.

| Роль | Назначение |
|---|---|
| `source` | `preset`, `wallpaper` или `manual`. Откуда взята палитра (этап 4). |
| `bg` | Основной фон. |
| `surface` | Поверхность панели и карточки. |
| `surface_alt` | Вторая поверхность (вложенные элементы). |
| `primary` | Главный акцент. |
| `secondary` | Второй акцент. |
| `accent` | Подсветка и фокус. |
| `text` | Основной текст. |
| `text_muted` | Второстепенный текст. |
| `border` | Границы и разделители. |
| `success` | Успех. |
| `warning` | Предупреждение. |
| `error` | Ошибка. |

### 2.3 material (Liquid Glass)

| Поле | Тип | Диапазон | Описание |
|---|---|---|---|
| `opacity` | float | 0.0-1.0 | Прозрачность поверхности. |
| `blur_radius` | int | 0-64 | Радиус размытия в логических пикселях. |
| `tint_strength` | float | 0.0-1.0 | Сила подмешивания цвета палитры. |
| `highlight_strength` | float | 0.0-1.0 | Яркость бликов. |
| `glow_strength` | float | 0.0-1.0 | Мягкое свечение. В упрощённом режиме 0. |
| `border_width` | float | 0-4 | Толщина границы. |

### 2.4 motion

| Поле | Тип | Описание |
|---|---|---|
| `duration_fast_ms` | int | Быстрая анимация (переключение сцены, 100-150 мс). |
| `duration_normal_ms` | int | Обычная анимация. |
| `duration_slow_ms` | int | Медленная (появление экрана, декоративная). |
| `easing` | string | Имя кривой для не-пружинных анимаций. |
| `spring.stiffness` | float | Жёсткость пружины. |
| `spring.damping` | float | Демпфирование. |
| `spring.mass` | float | Масса. |

Анимация успешного входа на SDDM не должна затягивать вход дольше
примерно одной секунды. На экране входа `duration_*` ограничивается
сверху этим значением при экспорте.

### 2.5 shape

| Поле | Тип | Описание |
|---|---|---|
| `radius_small` | int | Скругление мелких элементов. |
| `radius_medium` | int | Скругление карточек и кнопок. |
| `radius_large` | int | Скругление панелей и окон. |
| `spacing_unit` | int | Базовая единица отступов. |

### 2.6 typography

| Поле | Тип | Описание |
|---|---|---|
| `font_family` | string | Основной шрифт. |
| `font_family_mono` | string | Моноширинный шрифт. |
| `size_small` | int | Мелкий текст. |
| `size_body` | int | Основной текст. |
| `size_title` | int | Заголовки. |

### 2.7 effects

| Поле | Тип | Описание |
|---|---|---|
| `quality` | string | `simple`, `balanced`, `high` или `ultra`. |
| `liquid_glass` | bool | Включён ли эффект. |
| `spring_physics` | bool | Включена ли пружинная физика. |

`simple` - упрощённый вариант для слабого железа: тот же эффект без свечения
(`glow_strength` принудительно 0) и с меньшим разрешением. Пресеты `balanced`,
`high`, `ultra` задают уровень нагрузки, а не конкретную видеокарту.

## 3. Переопределения на виджетах

Любой виджет может переопределить часть токенов. Переопределение хранится
отдельно от темы и не сбрасывается при смене обоев:

```
"widget_overrides": {
  "clock": { "palette": { "primary": "#FFB86C" } },
  "player": { "material": { "opacity": 0.55 } }
}
```

Правила:
- переопределять можно любые поля из `palette`, `material`, `motion`, `shape`;
- незаданные поля берутся из активной темы;
- при смене обоев `palette.source = wallpaper` перезаписывает палитру темы,
  но не `widget_overrides`.

## 4. Экспорт в SDDM (`theme.conf`)

Экспортируется только подмножество, нужное экрану входа. Формат плоский
`ключ=значение`, без вложенности и без каких-либо данных пользователя.

Экспортируются:
- все роли `palette`;
- `material.opacity`, `material.blur_radius`, `material.tint_strength`,
  `material.highlight_strength`, `material.glow_strength`;
- `shape.radius_*`;
- `typography.font_family`, `size_*`;
- `motion.duration_*` (с ограничением для входа).

Не экспортируются: `widget_overrides`, `effects.*` (тяжёлые эффекты Hyprland
на экране входа недоступны), пути к файлам и любые сетевые адреса.

## 5. Миграции

- Каждая версия схемы получает функцию миграции `N -> N+1`.
- Файл с неизвестной более новой версией не перезаписывается: берутся значения
  по умолчанию, пользователю показывается сообщение.
- Перед миграцией делается копия старого файла рядом (`*.bak`).

## 6. Проверка (валидатор токенов)

Файл токенов считается допустимым, если:
- есть `schema_version` и он известен;
- все цвета в формате `#RRGGBB` или `#RRGGBBAA`;
- числа лежат в диапазонах из раздела 2;
- нет полей, не описанных в этой схеме;
- нет значений, похожих на пароль или токен.

Недопустимый файл отбрасывается, система продолжает работу со значениями по умолчанию.

## 7. Как токены попадают в систему (этап 4)

```
themes/<id>.json ──┐
                   ├─> hyprown theme ──> ~/.local/state/hyprdesk/tokens.json  (оболочка, Manager)
theme.json ────────┘   (ThemeEngine)  └> ~/.local/state/hyprdesk/theme.conf  (рамки окон, скругление)
 режим, тема, палитра обоев,
 widget_overrides
```

- `theme.json` - выбор пользователя (схема состояния 1): `mode` (`preset` или `wallpaper`), `preset`,
  палитра обоев и `widget_overrides`. Его же сохраняют снимки состояния (`recovery`).
- `tokens.json` и `theme.conf` - производные файлы: их можно удалить, `hyprown theme apply` пересоберёт.
- Режим `wallpaper`: палитра из обоев перекрывает только `palette` выбранной темы; материал, движение,
  форма и шрифты остаются от темы.
- Палитра из обоев (`palette_from_swatches`): тёмная тема; фон и поверхности почти серые в оттенке самого
  весомого цвета обоев; `primary`, `secondary`, `accent` - разные оттенки из картинки (минимум 28 градусов
  между ними, иначе производные от `primary`); `success`, `warning`, `error` держат смысловой оттенок;
  контраст с фоном не ниже 7 для `text` и 4.5 для остальных ролей. Серые и пустые обои дают сдержанную палитру.
- Извлечение цветов (`hyprown/colorx.py`): ffmpeg (или ImageMagick) уменьшает картинку или первый кадр видео до
  64x64, пиксели группируются в корзины по 4 бита на канал. Обои только читаются. Нет ffmpeg или файл
  не читается: палитра остаётся прежней, сессия не страдает.
- Переопределения виджета ищутся сначала по id (`clock-1`), потом по типу (`clock`).
- Перечитывание: оболочка следит за `tokens.json`, плюс опрос раз в 3 секунды на случай потерянного
  события при атомарной записи.
