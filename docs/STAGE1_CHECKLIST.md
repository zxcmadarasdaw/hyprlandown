# Этап 1: чек-лист проверки (Fedora)

Всё, что ниже, проверяется только на Fedora (live или установленной).
Версии Hyprland и других компонентов записать в `versions.txt`.

Перед началом: поставить `hyprland`, `kitty`, `fuzzel` (заглушки из конфигов),
`git`. Скопировать репозиторий на Fedora.

## A. Логика обёртки (работает на любом Linux, без Hyprland)

```
bash scripts/test-session-wrapper.sh
```
Ожидание: `PASS=18 FAIL=0`.

## B. Конфиг Hyprland без входа в сессию

1. Сначала выполнить шаг C1 (в конфигах пути `~/.config/hypr/...`).
2. Из запущенной сессии Plasma (live): `Hyprland -c hypr/hyprland.conf`.
   Hyprland откроется вложенным окном.
3. В терминале внутри него: `hyprctl configerrors`. Ожидание: пусто.
4. Если есть ошибки: записать текст ошибки и версию Hyprland. Синтаксис мог
   измениться между версиями, правим по тексту ошибки.

## C. Установка (по очереди, с проверкой отката)

1. Симлинки:
   ```
   bash scripts/link-configs.sh            # dry-run
   bash scripts/link-configs.sh --apply
   bash scripts/link-configs.sh --rollback # проверить откат, затем снова --apply
   ```
2. Сессии:
   ```
   bash scripts/install-session.sh         # dry-run
   sudo bash scripts/install-session.sh --apply
   ```
3. На экране входа должны появиться "Hyprland" и "Hyprland (safe)".

## D. Критерии этапа 1

- [ ] Сессия "Hyprland" стартует, `hyprctl configerrors` пустой.
- [ ] Сессия "Hyprland (safe)" стартует: сплошной фон, без Quickshell, видно уведомление.
- [ ] Аварийный выход (например `killall -9 Hyprland`) -> следующий вход
      в "Hyprland" стартует safe-сессию с уведомлением.
- [ ] Штатный выход (Super+Shift+E) -> следующий вход обычный.
- [ ] Штатная перезагрузка (`systemctl reboot` из сессии) -> следующий вход обычный.
- [ ] Выключение/перезагрузка с запущенной сессией не оставляет маркер
      (`ls ~/.local/state/hyprdesk/`).
- [ ] Откат: выбор "Hyprland (safe)" или Plasma на экране входа работает.

Журнал обёртки: `~/.local/state/hyprdesk/session.log` (причина каждого выхода:
`why=exit0|signal|signal-late|shutdown` или `аварийный выход code=...`).

## Ревью обёртки (Opus 5.5): принятые решения

- Сигнал TERM/HUP/INT обёртке снимает маркер сразу, до выхода Hyprland:
  SIGKILL от systemd по таймауту при выключении не оставит ложный маркер.
- Если Hyprland вышел с ошибкой, обёртка до 2 секунд ждёт сигнала, остановки
  системы (`systemctl is-system-running` = stopping) или закрытия сеанса
  (logind State = closing). Падение в обычной работе задерживает выход на 2 с.
- Маркер содержит token запуска, сессия снимает только свой маркер.
- Потеря питания и `kill -9` обёртки считаются аварией: следующий вход в safe.
- Штатный выход из safe-сессии (в том числе выбранной вручную) снимает маркер
  прошлой аварии: следующий вход обычный.
- Известное ограничение: если вторая сессия того же пользователя уже запущена,
  новый вход увидит её маркер и стартует в safe. Для одного монитора и одного
  пользователя это не мешает.

## Что может не сойтись и требует решения

- Новые версии Hyprland могут рекомендовать запуск через `start-hyprland`
  вместо `Hyprland`, и у него может быть своё восстановление после падений.
  Обёртка берёт имя из переменной `HYPRLAND_BIN`. Проверить версию на Fedora:
  если там `start-hyprland` со своим safe-режимом, решить, какой механизм
  главный, чтобы два восстановления не конфликтовали.
- Диспетчер `togglesplit` (Super+J) в новых версиях может требовать формы
  `layoutmsg, togglesplit`. `hyprctl configerrors` это не всегда ловит:
  проверить клавишу руками.
- На Fedora SELinux может блокировать запуск скрипта из `/usr/local/bin`
  при входе. Проверить `journalctl -b | grep -i avc`.
- В live-сессии состояние хранится в оперативной памяти и пропадает после
  перезагрузки. Проверку "аварийный выход -> safe" делать без перезагрузки,
  а перезагрузку на установленной системе.
