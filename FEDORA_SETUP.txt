ИНСТРУКЦИЯ: УСТАНОВКА HYPRLAND НА FEDORA (live и установленная система)
========================================================================

Что нужно: интернет, Fedora live (или установленная Fedora), доступ к терминалу.
Все команды выполняются в терминале по порядку. Не пропускай шаги.

Важно:
- Live-система работает в оперативной памяти: после перезагрузки всё,
  что установлено и настроено, пропадёт. Для проверки это нормально.
- Для клонирования пароль GitHub не нужен: репозиторий публичный.
- Команды с sudo спросят пароль пользователя live (см. подсказку в конце).


ШАГ 0. Обновить систему и поставить git
---------------------------------------
sudo dnf upgrade -y --refresh
sudo dnf install -y git curl unzip


ШАГ 1. Hyprland и базовые программы
-----------------------------------
sudo dnf install -y hyprland kitty fuzzel

Проверка: команда `Hyprland --version` должна выводить версию.
Версию записать в versions.txt (поле hyprland).


ШАГ 2. Звук, мультимедиа, видео-обои (для этапов 3 и 5)
-------------------------------------------------------
sudo dnf install -y wireplumber mpv

`wireplumber` даёт команду `wpctl`, которую использует громкость.

Для видеодекодирования на AMD (VAAPI):
sudo dnf install -y mesa-va-drivers

Для NVIDIA: НЕ ставить сейчас. Это отдельный этап (14), нужен RPM Fusion
и правильный драйвер. Пропускаем.


ШАГ 3. Quickshell (для этапа 2)
-------------------------------
Проверить, есть ли пакет в репозиториях Fedora:

dnf search quickshell

Если строка с quickshell есть:
sudo dnf install -y quickshell

Если поиск ничего не нашёл: НЕ придумывай имя пакета. Запиши вывод
команды `dnf search quickshell` и версию Fedora (`cat /etc/fedora-release`)
и пришли мне. Установку Quickshell решим отдельно (возможны COPR или сборка
из исходников, это решение владельца проекта).

Версию записать в versions.txt (поле quickshell).


ШАГ 4. Скачать репозиторий с конфигами
--------------------------------------
cd ~
git clone https://github.com/ИМЯ_ПОЛЬЗОВАТЕЛЯ/hyprland-dotfiles.git
cd hyprland-dotfiles

Заменить ИМЯ_ПОЛЬЗОВАТЕЛЯ на свой логин GitHub
(ссылку пришлёт владелец проекта; в ней будет точный адрес).

Проверка: `ls` должен показать папки hypr, scripts, docs и файлы
README.md, versions.txt, FEDORA_SETUP.txt.


ШАГ 5. Проверка логики обёртки (без Hyprland)
---------------------------------------------
bash scripts/test-session-wrapper.sh

Ожидание в конце: "Итог: PASS=18 FAIL=0".
Если не сходится: скопировать весь вывод и прислать.


ШАГ 6. Симлинки конфигов (сначала сухой прогон)
-----------------------------------------------
bash scripts/link-configs.sh

Показывает, что будет сделано, ничего не меняет.
Если всё понятно, применить:

bash scripts/link-configs.sh --apply

Откат, если что-то пошло не так:

bash scripts/link-configs.sh --rollback


ШАГ 7. Проверка конфига Hyprland
--------------------------------
Запусти Hyprland в окне из текущей сессии (если уже работаешь в Hyprland,
вложенный запуск тоже подходит):

Hyprland

Внутри открывшегося окна нажми Super+Enter (откроется kitty), затем
в терминале выполни:

hyprctl configerrors

Ожидание: ничего не выведено (пусто).
Если есть текст ошибки, скопировать его целиком и прислать.

Выход из Hyprland: Super+Shift+E.


ШАГ 8. Сессии для экрана входа (только установленная система, не live)
-----------------------------------------------------------------------
Для live-системы этот шаг не нужен. На установленной Fedora:

sudo bash scripts/install-session.sh            # сначала сухой прогон
sudo bash scripts/install-session.sh --apply    # применить

Откат:
sudo bash scripts/install-session.sh --remove


ЧТО ПРИСЛАТЬ ВЛАДЕЛЬЦУ ПРОЕКТА ПОСЛЕ ПРОВЕРКИ
---------------------------------------------
- версия Fedora:           cat /etc/fedora-release
- версия Hyprland:         Hyprland --version
- вывод шага 5 (тесты)
- вывод шага 7 (configerrors), если есть ошибки
- что сработало, что нет


ПОДСКАЗКА ПРО ПАРОЛЬ SUDO В LIVE
--------------------------------
В большинстве live-образов Fedora пароля нет или он не нужен для sudo.
Если спрашивает пароль и не принимает: открой заново live-сессию или
задай пароль командой `sudo passwd $USER`.
